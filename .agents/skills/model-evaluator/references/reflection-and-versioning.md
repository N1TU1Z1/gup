# 反思与版本规则

## 两维评价

分别记录：

| 决策质量 | 结果质量 | 解释 |
|---|---|---|
| 好 | 好 | 过程和结果均支持 |
| 好 | 坏 | 可能是概率内损失，不立即改模型 |
| 坏 | 好 | 运气盈利，必须保留错误 |
| 坏 | 坏 | 优先定位模型或执行缺陷 |

## 固定错误类型

- `data_error`：数据错误、陈旧或缺失。
- `causal_error`：因果链不存在或方向错误。
- `competitive_position_error`：忽略相对竞争者变化。
- `conversion_error`：行业或主题未转化为收入、利润或现金流。
- `capital_efficiency_error`：忽略资本投入与回报恶化。
- `probability_calibration_error`：概率长期高估或低估。
- `horizon_error`：基本面判断与持有期限错配。
- `execution_error`：触发、成交、减仓或退出执行偏差。
- `risk_control_error`：仓位、相关暴露或尾部风险错误。
- `missing_variable`：已有变量不能解释稳定分化。

## 反思记录

每次反思回答：

1. `T0` 当时可见的事实是什么？
2. 哪个预测被证实或推翻？
3. 错误属于模型、数据、期限、执行还是随机结果？
4. 当时遵守规则时的反事实动作是什么？
5. 哪个新证据可以在未来区分两种解释？

## 版本升级

单个案例只创建 `revision_proposed`。升级必须经过：

```text
提出修订 -> 历史压力测试 -> 样本外前向测试 -> 接受或拒绝 -> 新版本激活
```

新版本不得覆盖旧实验。保存父版本、修改原因、受影响变量、支持样本和反对样本。

`model_versions.status=active` 只表示该定义是新假设的默认版本，不代表已经验证。初始基线可以处于 active，但必须明确标记为未验证；后续版本仍须完成上述流程才能激活。
