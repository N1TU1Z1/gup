# 状态消除与概率赔率

## 三门逻辑的对象

三门逻辑更新的是同一预测问题下的未来状态分布，不是当前市场主状态。建立分区前冻结：

- `target`：要判断的结果变量。
- `horizon` 与 `settlement_at`：何时结算。
- `benchmark`：相对谁判断。
- `settlement_rules`：每个状态的可观察判定规则。
- `evidence_as_of`：更新时可见的信息截止点。

状态必须满足：

```text
Hi ∩ Hj = ∅  (i ≠ j)
H1 ∪ ... ∪ Hk = Ω
```

叙事名称不构成互斥条件。“技术反抽”和“指数护盘”可能同时发生，必须用结算变量、阈值和判定优先级把同一结果唯一分配给一个终局。仍有无法覆盖的结果时增加 `H_other`。

## State Elimination 的正式含义

“彩票逻辑”中的信息更新正式记为 `State Elimination`（状态消除/降权）。它不是“连续失败后更该成功”，也不是三门问题中“剩下的门必有奖品”的机械移植。

每条可靠新证据对每个未来状态只允许四类更新：

- `ruled_out`：冻结期限和结算规则已使该状态不可能成立，后验概率为零。
- `downweighted`：证据在该状态下较不可能出现，但该状态仍可发生。
- `unchanged`：证据不具区分力，或与已有证据同源。
- `upweighted`：证据在该状态下相对更可能出现。

`ruled_out` 必须是严格逻辑结论；“暂未创新低”“一次利空没有下跌”或“卖方今天没有出现”通常只能降权。每次更新至少记录：

```text
update_id、evidence_id、affected_state、update_type
causal_mechanism、likelihood_direction、reversible、reason
```

判断顺序是：先问可识别的失败机制是否真的被移除，再问哪些状态的相对概率应变化。例如产能退出、库存出清或约束解除若有独立证据，可能削弱对应失败状态；如果亏损、杠杆或需求恶化仍在累积，连续下跌不会提高成功概率。排除一个失败状态后，其他失败状态和 `H_other` 仍然存在，不能把剩余概率自动全部转给成功状态。

## 建立互斥终局

优先用少量可观测终局，而不是堆叠故事。悲观修复实验可以按以下骨架定制，但阈值必须在 T0 冻结：

1. `H_repanic`：在期限内触发预定义的再恐慌或回撤阈值。
2. `H_index_only`：未触发 `H_repanic`，指数稳定，但广度和高 Beta 确认失败。
3. `H_tactical_rebound`：未命中前两项，曾出现修复，但持续性确认在结算日失败。
4. `H_durable_repair`：未命中前三项，且结算日满足广度、风险偏好和相对价格确认。
5. `H_other`：其余可成交、可观察结果。

按 `settlement_priority` 从上到下只分配一次，保证互斥。若研究问题不同，应重新定义分区，不复用这组名称。

## 概率更新

贝叶斯表达用于约束更新方向：

```text
P(Hi | I) ∝ P(I | Hi) × P(Hi)
```

不要求在缺乏基准率时伪造似然数字。概率来源只允许：

- `calibrated`：来自冻结版本的样本外校准。
- `base_rate_adjusted`：有可审计基准率，并用当前证据调整。
- `scenario_judgment`：主观情景判断，必须给范围、反证和低/中置信度。
- `ordinal_only`：只表达相对升降，不输出百分比。
- `unavailable`：证据不足，保持空值。

使用点概率时必须满足 `Σp=1`。使用区间时至少满足：

```text
Σlower_i ≤ 1 ≤ Σupper_i
```

区间一致只说明存在可行分布，不代表已经校准。不能把“相对可能性上升”自动翻译为 65% 或 70%。

## 相关证据与状态消除更新

高开、指数上涨、上涨家数增加和高 Beta 反弹可能来自同一个风险偏好因子。先按证据族分组：

```text
breadth、risk_appetite、liquidity_supply、news_reaction、fundamental、valuation
```

同族信号用于增强该族置信度，不作为独立似然连续相乘。只有已经建模联合分布或证明近似条件独立时，才数值相乘多个似然。

每次更新保存：支持哪些状态、反对哪些状态、是否与已有证据同源、失败机制是否真的被移除，以及更新前后是点概率、区间还是仅顺序变化。任何数值更新后都必须重新归一。

## 状态消除后的彩票赔率桥

彩票逻辑比较的是联合终局的概率与可成交净赔付，不是追逐小概率暴涨：

```text
EV(h) = Σ[P(Ji) × NetPayoff(Ji, h)]
```

`Ji` 可以包含基本面、市场状态和重定价路径，但只保留会产生不同赔付或风险的联合状态，避免无意义的笛卡尔积。

进入 EV 的 `Ji` 本身也必须互斥且穷尽，概率和为 1。若只是给每个 `Hi` 附加同一组条件风险，不要重新生成一套未归一的联合概率。

本技能向 `$trade-lifecycle` 传递：

- 互斥终局及其概率来源。
- 每个终局的经济含义、催化和失效条件。
- 需要估计的价格/估值赔付输入。
- 流动性、跳空、跌停和期限风险清单。

交易层补充成本、滑点、T+1可执行性、`PR(h)` 和净赔付后计算 EV。

## 尾部风险不得重叠

若“跌停无法退出”可能在 `H_repanic`、`H_index_only` 等多个状态中发生，它不是额外互斥终局。只能二选一：

1. 作为每个相关终局的条件损失和条件概率；或
2. 展开为互斥联合终局，例如 `H_repanic_and_limit_down` 与 `H_repanic_without_limit_down`。

禁止在保留原状态概率不变的同时，再附加一个重叠尾部状态参与 `ΣpR`，否则概率和期望值会重复计算。

## 输出纪律

- 当前状态 `M_t`、未来状态 `H(h)`、基本面概率 `PF` 和重定价概率 `PR(h)`分栏保存。
- 没有明确期限和结算规则时，只能列竞争假设，不能输出胜率或Brier可结算概率。
- 胜率不能替代赔率；高胜率、负期望的方案应被拒绝。
- 改变状态全集、判定优先级或结算阈值属于模型版本变化，不得覆盖旧实验。
