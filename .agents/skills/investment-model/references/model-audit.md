# 证据与互斥审计

冻结任何带概率结论前执行本审计。目标不是消除所有不确定性，而是阻止缺失事实、重叠状态、相关信号和未来数据被包装成精确模型。

## 证据台账

每个关键主张至少保存：

```text
claim_id、claim_type、claim
source_id、source_kind、published_at、observed_at、reporting_period
raw_value、unit、formula、derived_value
available_at_t0、freshness、evidence_family
```

`claim_type` 只允许：

- `observed`：原始来源直接支持。
- `derived`：由可追溯原始值和明确公式计算。
- `inferred`：存在替代解释的推断。
- `unknown`：缺少关键证据，值保持 `null`。

审计规则：

- `observed` 没有来源、期间或可得时间时降为 `unknown`。
- `derived` 没有原始输入、单位或公式时不得输出数值。
- `inferred` 不得改写成“已证明”“已经排除”或 `confirmed`。
- 新闻标题不能单独证明订单、收入、利润、政策落地或消息强度。
- 没有查到反证不等于反证不存在；标记搜索范围和缺失项。
- 事实过期时标记 `stale`，不用静态知识补写当前状态。

## 幻觉审计

逐项检查：

1. 是否出现无来源的精确数字、日期、排名、市场份额或概率。
2. 是否把主观情景概率写成回测概率。
3. 是否把公司公告、管理层表述或媒体转述直接当作已实现结果。
4. 是否把市场/行业结论直接赋给个股。
5. 是否用未来收益、后来修订的公告或收盘后数据反填 T0。
6. 是否把价格上涨解释成基本面改善，或把情绪衰竭写入 `PF`。
7. 是否把“缩量+广度改善”唯一解释为卖压耗尽，而忽略参与度不足、权重结构或数据口径变化。
8. 是否在没有可比事件和冻结基准时声称“坏消息越来越失效”。
9. 是否把连续失败、连续下跌或某个坏结果多次出现解释为“下一次成功概率更高”。
10. 是否把仍可发生的状态写成 `ruled_out`，而不是 `downweighted` 或 `unchanged`。

任何关键项失败时，删除无支持结论或降为 `unknown/inferred`，并记录阻断项。

## 互斥与穷尽审计

### 当前状态

- 一个时点只能有一个 `primary_regime`。
- `transition_candidate` 只是候选迁移，不是第二个当前状态。
- 数据不足时使用 `unclassified`，不为了完整展示强制分类。

### 未来状态

- 所有状态使用同一目标、期限、基准和结算时点。
- 任意两个结算事件不能同时为真；若可能同时为真，必须增加判定优先级或展开联合状态。
- 状态并集覆盖所有可观察结果；否则增加 `H_other`。
- 经济驱动情景若没有结算规则，只能作为因果叙事，不能直接进入概率和EV计算。

### 概率

- 点概率和等于1；允许最小数值舍入误差，但必须记录。
- 区间概率满足可行性条件，并标注未校准。
- 不把当前 `E1-E6` 状态概率、未来终局概率、`PF` 和 `PR(h)`相加或混成同一分布。
- 尾部事件与主情景重叠时，改为条件损失或联合终局。

## 重复计数审计

给每条证据分配唯一的 `evidence_family`。同一原始序列派生的多个指标默认相关，例如：

- 上涨家数、Breadth和上涨占比。
- 小盘相对收益、高 Beta收益和题材股收益。
- 成交缩量、换手下降和成交额下降。
- 同一公告的多篇新闻转述。

相关指标可以互相校验数据质量，但不能被描述成多个独立信息连续打开多扇门。无法估计相关结构时，采用保守合并或定性更新。

## 状态消除与迟滞审计

- 每个 `ruled_out` 状态都必须有冻结的结算规则和使其不再可能成立的证据；缺一项即降为 `downweighted`。
- 检查概率上升是否来自可识别失败机制被削弱，而不是赌徒谬误、价格跌幅或“坏消息次数”。
- `state_elimination_updates` 必须引用证据台账，并说明同源性、可逆性和似然方向。
- `primary_regime` 与 `regime_lock.active_engine` 必须分栏；二者暂时不同不构成互斥失败。
- 迟滞规则必须在 T0 冻结并包含非对称进入/退出条件、最短驻留期及连续确认数。事后修改任何一项必须新建模型版本。
- 未经校准不得使用精确概率阈值控制切换；可使用预先冻结的状态序列和去重证据确认规则。
- 紧急回退条件必须预先定义，不能在结果出现后添加例外。

## 审计结果

输出一个结论：

- `pass`：关键事实可追溯，状态互斥穷尽，概率检查通过。
- `qualified`：可以输出方向或宽区间，但存在未校准概率、缺失证据或相关性问题。
- `fail`：关键事实、T0边界、状态分区或概率归一失败；不得输出精确PF、状态概率或赔率结论。

至少记录：

```text
hallucination_status
exclusivity_status
exhaustiveness_status
probability_status
double_counting_status
state_elimination_status
hysteresis_status
blockers、downgraded_claims、required_evidence
```
