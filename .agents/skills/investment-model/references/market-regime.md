# 市场状态与双引擎

## 目标与边界

市场状态不是一个加入基本面总分的因子，而是条件变量和路由器：

```text
P(上涨_h | F, V, S, M)
```

- `F`：公司基本面事实与 `PF`。
- `V`：市场隐含预期和价格兑现程度。
- `S`：情绪水平及其变化。
- `M`：市场状态。

本技能冻结 `M`、证据和研究引擎，不估计买卖点或 `PR(h)`。市场悲观不能提高 `PF`，市场乐观也不能证明经济价值改善。

## 五层观测

### 1. 市场广度

至少记录上涨/下跌家数、涨跌停、涨跌超过 5%、创新高/新低数量。可使用：

```text
Breadth = (上涨家数 - 下跌家数) / 有效股票数
```

指数涨跌只作补充，不能代替广度。

### 2. 赚钱效应

观察已经形成的历史队列，例如昨日涨停、昨日高换手强势股或某日等权买入组合，在截至 T0 已经走完的 1/3/5 日窗口表现。

- T0 当天只能使用已成熟队列。
- 尚未发生的未来收益只作为待验证标签，不能成为当日特征。
- 队列定义、剔除规则和交易成本必须冻结，禁止按结果更换样本。

### 3. 风险偏好

比较高 Beta 与低 Beta 资产的相对收益，并控制市场方向：

```text
RiskAppetite = R_high_beta - R_low_beta
```

可使用小盘/大盘、成长/价值、题材/红利等稳定组合。指数上涨但 `RiskAppetite<0` 时，不得标记为标准 Risk-on。

### 4. 消息边际反应

重点不是消息标题，而是可比较信息出现后的异常价格反应。只能选择一种预先冻结的方法：

```text
简单法：AbnormalReturn = R_stock - R_frozen_benchmark
回归法：AbnormalReturn = 预先冻结回归模型的残差
```

`frozen_benchmark` 可选择市场或行业基准。没有预先估计系数时，不得临时同时扣除市场和行业收益，以免重复调整；使用回归法时保存估计窗口、系数、样本和基准定义。

分别跟踪：

- `bad_news_resistance`：类似负面信息下，异常收益是否从大幅为负逐步接近零或转正。
- `good_news_elasticity`：类似正面信息下，异常收益是否持续下降，提示乐观预期趋于饱和。

只有消息强度可标准化时才使用 `价格反应/消息强度`。否则记录事件类别、强度等级、预期差、窗口和异常收益，不伪造连续精度。单次抗跌或单次利好失效只形成观察，不确认状态转换。

一条价格序列只能归入一个主要证据族。若“上涨家数扩大”“高 Beta 修复”和“强势股溢价”来自高度重叠股票集合，应记录相关性并降权，不能当作三次独立确认。

### 5. 成交与拥挤

价格与成交联合解释：

| 价格 | 成交 | 常见解释 | 必要复核 |
|---|---|---|---|
| 上涨 | 放量 | 风险偏好扩张候选 | 广度与高 Beta 是否同步 |
| 上涨 | 缩量 | 买盘持续性存疑 | 是否仅权重拉升 |
| 下跌 | 放量 | 恐慌或去杠杆 | 强制卖压是否继续 |
| 下跌 | 缩量 | 卖压衰竭候选 | 坏消息是否失效、是否停止创新低 |

缩量下跌本身不能确认底部。

## Level、方向与加速度

同时冻结：

```text
S_t   = 当前情绪水平
ΔS_t  = S_t - S_(t-1)
Δ²S_t = ΔS_t - ΔS_(t-1)
```

重点区分：

- 水平很低且 `ΔS<0`：悲观仍在加速。
- 水平很低、`ΔS<0` 但 `Δ²S>0`：恶化速度下降，只进入衰竭观察。
- 水平很低且 `ΔS>0`，同时坏消息钝化和相对强度改善：潜在 `E5→E6`。

不要求强行生成统一的 `SentimentScore`。数据不足时可以用有序状态、方向和置信度表达。

## 唯一主状态分类

先冻结 `threshold_set_id`、历史窗口、情绪水平分位和 `ΔS` 方向阈值。阈值必须用 T0 前数据确定；没有可用阈值或五层数据不足时输出 `unclassified`，不强行选择 E1-E6。

对数据充分的观察按以下优先级分类，命中后停止，因此六个主状态互斥：

1. `Level=high`：若 `ΔS>0` 且风险偏好或广度确认，记 `E1`；否则记 `E2`。
2. `Level=low/extreme_low`：若恢复确认门通过，记 `E6`；否则记 `E5`。
3. 非高、非低状态下，若 `ΔS<0` 且悲观证据扩散，记 `E4`。
4. 其余数据充分状态记 `E3`。

恢复确认门要求：

- `ΔS>0`，或 `ΔS` 不再为负且 `Δ²S>0`；并且
- 至少两个去重后的证据族确认，其中至少一个来自消息反应或相对价格拒绝下跌。

尚未通过恢复确认门时，主状态仍为 `E5`，另记 `transition_candidate: E6`；禁止输出两个当前主状态或用 `E5→E6?` 代替分类。

## 六状态机

| 状态 | 定义 | 关键证据 | 默认动作 |
|---|---|---|---|
| `E1` 极度乐观扩张 | 水平高且风险偏好继续扩张 | 广度、赚钱效应、高 Beta 与成交共振 | 价值/盈利兑现研究，同时检查拥挤 |
| `E2` 乐观边际降温 | 水平仍高但 `ΔS` 或 `Δ²S` 转弱 | 好消息弹性下降、广度分化 | 降低追逐充分定价故事的优先级 |
| `E3` 中性/分化 | 未命中高位、低位和悲观扩散规则 | 行业和风格分化 | 相对强弱与独立事件研究 |
| `E4` 悲观加速 | 非极低水平且悲观继续扩散 | 广度恶化、高 Beta 补跌、坏消息仍有效 | 防守，不主动抄底 |
| `E5` 低位悲观未确认修复 | 水平低或极低，恢复确认门未通过 | 极端广度、去杠杆、赚钱效应差 | 建观察池，不把极值或候选转折当买点 |
| `E6` 悲观衰竭/潜在反转 | 水平仍低且恢复确认门通过 | `ΔS/Δ²S` 改善、坏消息钝化、相对强度确认 | 情绪错价研究，交给交易层确认 |

只有 RSI、跌幅或缩量不得确认 `E6`。状态允许持续和回退，例如 `E5→E5`、`E6→E4`；状态迁移是相邻时点的比较，不是一个时点同时拥有两个主状态。

## 六状态机的迟滞锁

保留 `E1-E6` 作为唯一当前状态机，同时把“观察到的状态”和“实际启用的研究引擎”分开：

```text
primary_regime_t = classify(M_t)
active_engine_t  = hysteresis(primary_regime_t, L_(t-1), frozen_lock_rule)
```

迟滞锁 `L_t` 的目的，是防止状态在临界区小幅波动时频繁切换引擎，不是制造第二个市场状态。至少冻结：

- `lock_rule_id` 与规则版本。
- 各路线不同的进入条件和退出条件；禁止使用完全相同的单一阈值来回切换。
- `minimum_dwell_observations`：切换后的最短驻留观察数。
- `required_consecutive_confirmations`：候选路线需要连续确认的观察数。
- 数据缺失、盘前/盘后口径变化和急剧反向冲击时的回退规则。

若使用概率门槛，概率必须来自已校准或可审计的基准率，而且进入与退出门槛之间必须留有冻结的迟滞区间。未完成校准时，不得预设看似精确的百分比；改用冻结的状态序列、证据族确认数和驻留观察数。

每次观察都先更新 `primary_regime`，再评估锁：

1. 未达到切换条件时，保存新的 `candidate_engine`，但保持 `active_engine` 不变。
2. 同时满足非对称进出条件、最短驻留期和连续确认数后，才更新 `active_engine` 与 `entered_at`。
3. 出现冻结的紧急回退条件时，可以提前退出，但必须记录触发证据，不能事后新增例外。
4. `primary_regime`、`transition_candidate` 和 `regime_lock` 分栏保存；迟滞锁不改变 `PF`，也不把 `E5` 改写成 `E6`。

引擎路线可包括 `value_earnings`、`relative_event`、`defensive_watch`、`sentiment_exhaustion` 和 `reversal_confirmation`。具体映射与切换条件属于模型版本，不把某条未经验证的状态路径写成永恒规则。

## 三类引擎

### Value/Earnings Engine

主要用于 `E1/E2`：

```text
ValueRealizationGap = ΔEconomicValue - ΔPriceExpectation
```

优先研究盈利、现金流、ROIC、份额和订单兑现超过价格隐含预期的公司。若连续好消息的异常收益递减，把“预期已充分”列为反证。

### Sentiment Exhaustion Engine

主要用于 `E5/E6`。寻找的不是跌幅最大，而是最坏状态的相对可能性正在下降：

- 基本面生存底线、资产负债表、治理和数据可靠性通过。
- 坏消息反应钝化，市场/行业下跌时相对抗跌。
- 卖压和拥挤释放出现可复核变化。
- 永久性价值损失假设没有被证实。

情绪衰竭只能提高“错价值得研究”的优先级，不能把基本面失败改成成功。

### Reversal Confirmation Engine

主要用于状态转换。最强组合是：

```text
坏消息失效 + 好消息重新有效
```

先写出竞争假设，例如“强制卖压仍占主导”“风险偏好稳定”“基本面永久受损”“反转开始”，再用新证据更新各状态的相对可能性。不得把每个信号描述成确定性排除一扇门。

## 冻结与防泄漏

- 冻结 `evidence_as_of`、盘前/盘后口径、数据发布时间、状态、置信度和反证。
- 收盘数据只能用于收盘后状态；盘前模型不能读取当天收盘广度。
- 新闻使用首次可获得时间，不使用后来修订内容反填 T0。
- 回测时每天只使用当时可获得的数据，状态阈值在验证期前确定。
- 原状态和路由锁只能追加观察；改变状态定义、阈值、迟滞条件或引擎规则时创建新模型版本。
- `E1-E6` 只描述当前市场状态；未来“再恐慌、指数护盘、技术反抽、持续修复”等必须另建同期限的互斥结算状态。

## 最小输出

```text
observed_at、session_basis
SentimentLevel、ΔSentiment、Δ²Sentiment
唯一primary_regime、transition_candidate、分类规则与阈值版本
五层去重证据、状态反证、数据充分性
regime_lock、active_engine、candidate_engine、迟滞规则与切换理由
engine_route、路由理由、基本面底线
下一确认事件、回退条件、缺失数据
```
