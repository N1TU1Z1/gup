# 投资研究工作流

将研究组织为可追溯的状态机，而不是一次性荐股回答。只编排已有能力并检查数据契约，不在本技能内重复计算市场、公司或绩效指标。

## 路由

| 用户意图 | 使用能力 | 必须取得的输出 |
|---|---|---|
| 全盘、竞价、盘中扫描、热力图 | `$stock-screener` | `scan_run_id`、数据时间、覆盖基数、候选与数据质量 |
| 公司、行业、反转或主题兑现研究 | `$investment-model` | `hypothesis_id`、`model_version`、冻结假设、PF与失效条件 |
| 买点、卖点、条件单、持仓跟踪 | `$trade-lifecycle` | `plan_id`、PR(h)、触发/失效/退出条件与下一复核时间 |
| 胜率、复盘、模型验证与反思 | `$model-evaluator` | `experiment_id`、评价期限、绩效、错误归因与修订状态 |

只处理单一意图时直接进入对应能力。用户要求完整流程时，按上表顺序执行；前一步缺少关键字段时停止后续结论，不以自然语言猜测缺失状态。

## 统一标识与时间

关键记录必须使用稳定标识串联：

```text
scan_run_id -> model_version -> hypothesis_id -> probability_estimate_id -> plan_id -> experiment_id
```

- 每个事实保存 `data_as_of` 或 `evidence_as_of`。
- 盘中、收盘、报告期和模型评价时间不得混用。
- 冻结后的假设只能追加观察，不得用未来数据覆盖。
- 用户未确认券商条件单或成交时，只能记录本地计划，不能标记已执行。

## 每日模式

### 开盘前

读取最新持仓、开放计划、到期实验和上一交易日市场状态。输出今天必须复核的持仓与风险，不自动新增交易。

### 竞价与盘中

扫描产生候选后，只有完成实时刷新和关键证据检查的候选才能进入投资建模。已经持有或有开放计划的股票优先更新卖出窗口、失效条件和下一触发。

### 收盘后

冻结当日新增假设与实验，追加持仓观察，结算已经到期且数据完整的实验。未到期样本保持开放，不进入胜率。

## 完整性检查

在给出综合结论前必须披露：

1. 当前处于哪一阶段。
2. 数据截至时间和缺失项。
3. 已生成的稳定标识。
4. 下一次观察或评价时间。
5. 哪些动作只是研究计划，哪些已由用户确认执行。

行情、持仓或模型证据不足时，明确停止在哪一层，不为凑齐流程编造后续输出。
