# 交易生命周期

交易层只决定“何时以及在什么风险下行动”，不得把价格波动反向改写成新的基本面事实。

## 开始前

- 处理状态迁移或持续跟踪时读取 [状态机](references/state-machine.md)。
- 制定触发、仓位和退出条件时读取 [风险与执行](references/risk-and-execution.md)。

没有 `hypothesis_id`、冻结时间、失效条件或证据截止时间时，只能生成观察清单，不能生成积极交易结论。使用彩票赔率桥时，若上游 `model_audit` 失败、未来状态不互斥穷尽或概率未归一，同样只能观察，不能计算 EV。

## 工作流程

1. 读取冻结假设与 `PF`，保持原值不变。
2. 明确持有期限 `h`，依据市场环境、资金、流动性、筹码与价格位置估计 `PR(h)`。
3. 优先读取上游 `state_partition` 与 `lottery_odds_bridge`。把经济叙事情景转成同期限、互斥且穷尽的可结算联合终局，通过概率检查后计算扣除成本的期望值。
4. 保存入场触发、确认条件、基本面失效、价格失效、减仓、退出和到期条件。
5. 对现有持仓优先检查退出窗口、失效状态与下一观察时间，再讨论新增仓位。
6. 用户确认券商成交或条件单后才能更新为已激活或已执行；截图不完整时保留不确定性。

## 强制边界

- 普通A股执行T+1；当日新买股票不能把盘中止损写成可立即成交。
- 止损价是失效阈值，不是成交保证。跳空、跌停和流动性必须进入尾部情景。
- 尾部事件若可能发生在多个主情景中，作为条件损失或展开为互斥联合终局；不得在原概率分布之外重复增加一个重叠尾部概率。
- 主观概率必须保留 `probability_source`，不得在交易层把 `scenario_judgment` 改写成 `calibrated`。
- `planned` 仅表示本地计划；没有订单编号或用户确认时不得写成券商已创建。
- 开放持仓必须设置 `next_review_at`。出现价格触发、基本面证据变化或到期事件时追加观察记录。
- 新证据改变基本面因果链时，交回 `$investment-model` 建立新版本；本技能不能覆盖 `PF`。

## 输出

至少包含：

```text
plan_id、hypothesis_id、holding_horizon
PR(h)、情景期望值、成本与尾部风险
互斥/穷尽/概率和检查、概率来源
入场触发与确认、失效、减仓、退出和到期条件
当前生命周期状态、下一复核时间、条件单确认状态
```
